# Mr. Sky Website Analytics — Safe Setup and Verification

## Purpose
Measure genuine visits to the public Mr. Sky / Omni-Hub GitHub Pages website separately from GitHub repository views and clones.

Live site: https://eshanmehra20-web.github.io/mr-sky-app/

## Current state
- The existing Pages site is a static HTML site generated by the Omni-Hub workflow.
- GitHub repository Traffic (views/clones) is not the same as website analytics.
- The current website source does not yet contain a verified third-party analytics property ID.
- Therefore analytics must be described as **not yet installed / not yet verified** until the owner configures a provider and a test event appears in its dashboard.

## Recommended free-first setup
Evaluate a privacy-friendly hosted analytics service such as GoatCounter or Cloudflare Web Analytics. Check current free-tier terms, privacy documentation, regional requirements, and account eligibility before choosing. Do not assume a service is free forever or that every feature is included.

## Installation checklist
1. Owner selects the provider and creates the website property.
2. Obtain the exact site code / measurement ID / script from that provider.
3. Add only the provider-issued script to the HTML template used by the generator, not only to generated output that will be overwritten.
4. Keep provider IDs public only if the provider documents them as publishable identifiers. Never put API secrets or write tokens in client-side HTML.
5. Add a concise privacy notice and any consent controls required for the chosen provider and audience.
6. Deploy through a reviewed pull request.
7. Open the live website in a clean browser session and confirm the test page view appears in the provider dashboard.
8. Record the date, provider, property identifier (not a secret), tested URL, and verification result.
9. Check again after several hours and after 24 hours; small traffic can be delayed or aggregated.

## Metrics and interpretation
- Page views are page loads, not necessarily people.
- Unique visitors are approximate provider-defined browsers/devices, not verified identities.
- Returning visitors are provider-defined repeat browsers/devices.
- Referrers can be missing because of privacy controls, apps, or browser behavior.
- GitHub clones may include CI, automation, bots, or other machines. GitHub does not reveal the identity of individual cloners in ordinary traffic reports.
- Do not infer that zero views means nobody has ever seen the site; use the selected analytics provider's verified date range and setup status.

## Privacy guardrails
- Do not fingerprint users or try to identify named visitors.
- Do not collect names, email addresses, precise location, or sensitive attributes for basic traffic measurement.
- Minimize retention and use aggregate reports.
- Disclose analytics honestly and respect consent requirements.
- Exclude internal test traffic only using supported, documented provider controls.

## Acceptance test
Analytics is **LIVE and VERIFIED** only when all are true:
- A real provider property exists.
- The exact provider script is in the HTML source template.
- The deployed public page loads the script without errors.
- A test visit appears in the provider dashboard.
- Privacy notice/consent requirements have been reviewed.

Until then, report: **Tracker plan committed; live analytics not yet activated.**
